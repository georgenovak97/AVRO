# ADR 0003 — Strict unknown policy for quality filters

Статус: Accepted  
Дата: 2026-08-12

## Контекст

Complexity / quality-флаги Family Browser (`shared_only`, `no_imported_cad`,
`limit_*`) опираются на кэш инспекции `family_meta`.

Старое поведение при отсутствии кэша:
- count-поля читались как `0`;
- `shared_only` / `no_imported_cad` просто пропускали семью.

Итог: на неиндексированной библиотеке фильтр «без кучи типов» выглядел
как «все проходят» — ложное доверие к UI.

## Решение

**STRICT unknown** для всех quality-флагов, которым нужен inspect-cache:

1. Meta usable только если объект есть и `meta["ok"] is True`.
2. Если флаг активен и meta не usable → семья **не проходит** фильтр.
3. Если meta usable → обычное сравнение с лимитом / булевым условием.
4. Флаги комбинируются по **AND**.
5. `not_huge` использует `fi.size_kb` со сканирования диска и **не** требует
   inspect-cache; если размер неизвестен при активном флаге → fail.

Лимиты по умолчанию (fixed, без UI-input):
- formulas: 5
- остальные count: 10
- size: 5 MB

Реализация: pure-модуль `lib/family_browser_quality.py` + делегирование из
`FamilyBrowserDialog._passes_quality_flags`.

## Последствия

Плюсы:
- фильтры не врут на пустом индексе;
- поведение покрывается unit-тестами без Revit;
- подталкивает к команде «Обновить индекс» (шаг A2).

Минусы:
- до индексации complexity-фильтры дают пустую/урезанную выдачу —
  это ожидаемо и честно;
- нужен UI-индикатор покрытия индекса (шаг A3).

## Альтернатива (отклонена сейчас)

SOFT unknown: unknown проходит, в UI счётчик «N без данных».
Отложено: проще сначала strict + индекс, soft можно добавить флагом позже.
